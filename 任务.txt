一、项目目标
只搬运 TFC 的食物物品及其合成方式，并大幅简化：

不要 TFC 的营养系统、腐败系统、水分系统。

不要 TFC 的额外动物和衍生物。

TFC 的锅、炉灶等自定义工作方块全部用农夫乐事的工作方块代替。

种子和作物按原版机制注册和种植。

大桶保留，但改造成一个“可保存流体的无 UI 储罐”：右键用桶交互存/取流体，没有 GUI，没有发酵进度。容量为 1000B（即 1,000,000 mB）。

二、具体规则
1. 食物物品

只保留饥饿值和饱和度。

使用 NeoForge 26.1.2 的 FoodProperties 和 Consumable 组件。

使用 Mojang 官方映射，不要用 net.minecraftforge.* 包，要用 net.neoforged.*。

每个食物注册一个简单的 Item 类，不需要营养标签。

2. 种子和作物

按原版机制注册作物方块和种子物品。

生长条件只用：耕地 + 水 + 光照。

不需要 TFC 的土壤肥力、湿度、温度、季节系统。

3. 大桶（关键改动）

注册一个方块 tfc_food_port:barrel（或你建议的 ID），方块本体继承 Block 并实现 EntityBlock。

添加一个方块实体 BarrelBlockEntity，存储一个 FluidStack。

容量：1000B = 1,000,000 mB。

无 GUI。交互方式：玩家手持桶（空桶/水桶/牛奶桶等）右键大桶时：

空桶 + 大桶内有流体 → 取出 1000 mB 流体到桶里（如果大桶内流体不足 1000 mB，则全部取出）。

装有流体的桶 + 大桶为空或流体相同且未满 → 存入 1000 mB 流体（如果剩余空间不足 1000 mB，则存入剩余空间）。

其他情况右键无反应。

大桶的合成配方：原版半砖围一圈（有序合成，3x3 外圈 8 个半砖，中间空）。

大桶的模型和材质：简单方块模型即可，可以使用原版木桶材质或 TFC 大桶材质。

大桶的食物相关配方（腌制、发酵等），全部转为农夫乐事烹饪锅或原版工作台配方，不需要在大桶里实现。

大桶需要实现 IFluidHandler 能力（NeoForge Capability），以便其他模组的管道可以与之交互（可选，如果你不需要管道交互可以省略）。

4. 工作方块和配方

不要实现 TFC 的锅、炉灶、奶酪布、咸水。

所有 TFC 大桶、锅、炉灶、奶酪配方，全部转为：

农夫乐事烹饪锅配方：farmersdelight:cooking

农夫乐事切菜板配方：farmersdelight:cutting

原版工作台配方：minecraft:crafting_shaped / crafting_shapeless

原版熔炉/烟熏炉配方：minecraft:smelting / smoking

奶酪链条：

凝乳酶：由原版牛或羊掉落（修改战利品表）。

生奶酪：农夫乐事烹饪锅（牛奶 + 凝乳酶）。

陈化奶酪：熔炉/烟熏炉烧生奶酪。

不要奶酪布，不要咸水。

5. 动物

只保留原版动物（牛、猪、羊、鸡、兔）。

不要 TFC 额外动物。

修改战利品表，让牛/羊额外掉落凝乳酶。

三、输出要求
先输出完整的物品和方块清单：

列出所有要搬运的 TFC 食物、种子、材料、大桶方块。

每个物品给出：英文 ID、中文名、饥饿值、饱和度、获取方式。

大桶方块单独说明：方块 ID、方块实体、容量（1000B）、交互逻辑。

然后逐个生成代码和配方：

每次只处理一个食物或一个方块。

输出格式：先给 Java 类，再给需要的配方 JSON。

对于大桶，请单独生成：方块类、方块实体类、交互逻辑、合成配方 JSON。

使用 NeoForge 26.1.2 的 API：

方块注册用 DeferredRegister.Blocks

方块实体注册用 DeferredRegister.BlockEntityTypes

物品注册用 DeferredRegister.Items

流体处理参考 NeoForge 的 IFluidHandler 和 FluidStack

使用 net.neoforged.* 包，不要用 net.minecraftforge.*

不要修改 build.gradle，只生成 Java 代码和 resources 下的 JSON 文件。
